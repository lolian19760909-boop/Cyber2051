# 酒馆卡 3.0.0 交接（2026-11-01）

目的：把网页端这一轮更新收敛成**酒馆版 3.0.0 角色卡**交付。作者已拍板三个决定：①配套预设名升 **V0.13**；②Suite 的 motion 修复**随本次发 0.4.1**；③老玩家升级走**卡内更新**（需升级清单）。

## 环境与启动序列（新电脑从这里开始）

1. 仓库是**私有**的：用作者的 GitHub 账号登录后 clone `https://github.com/lolian19760909-boop/Cyber2051.git`；
2. Node ≥22（根 package.json engines）、git（需支持 submodule）；
3. `git submodule update --init`（拉取 Suite 子模块，已在 0.4.1）；
4. 仓库根 `npm install`（acorn 等构建依赖；upgrade-tool 等工具按仓库根 node_modules 解析）；
5. 无需从旧电脑传任何文件：`旧版来源.json` 已精简为哈希登记（135 条历史版本名+sha256，约 20KB，已入库）——升级清单只消费这两个字段，无需历史卡本体。

## 背景一页话

网页端今天上线到 35acf79（issue #28 全链收官）。**卡片源码自 2.3.33 交付后零改动**（git 可证：卡片源码只有初始 import 提交）。今天与酒馆卡相关的变更只有两处：build.cjs 版本常量 2.3.33→3.0.0；paired.cjs 预设适配层三笔（squash_system_messages=true、argon压制尾部 3beb259e… 关、快速思维链 64f1335c… 开）。网页引擎的修复（开局结构/转储 user/宽容校验/存档热更弹窗/role-class）全部是网站引擎专属，**酒馆卡不需要移植**。

## 实现步骤（按序）

1. **配套预设升 V0.13**：`工程文件/工具/构建/预设/paired.cjs` 里 `name:'Izumi_东京都2051改版V0.12'` 改为 V0.13（reborn profile 的名字按同理处理，如沿用则不动）。冻结原版（`工程文件/卡片源码/预设/原版/Izumi-1022.json`、`喵赛亚-1.5.json`）有 sha256 锁，**不能动**。
2. **重建配套预设**：`node -e "require('./工程文件/工具/构建/预设/paired.cjs').build({write:true})"`（在仓库根执行），产物落在 `工程文件/.cache/build/`。**验收三点**：`squash_system_messages==true`；prompt_order 中 `3beb259e-7516-41c9-8657-fd56cac8e628`（argon尾部）enabled==false；`64f1335c-52cd-4d6c-93d1-77cc99b0c76c`（快速思维链）enabled==true。注意 `.cache/` 不进 git，产物留在本机。
3. **构建酒馆卡**：`node 工程文件/工具/构建/当前/build.cjs` → `工程文件/.cache/build/东京都2051-V3.0.0.json`。构建自带 schema 模板指纹校验（`数据/schema.js` 与模板漂移会构建失败——那是防呆，不是 bug）。
4. **Suite 0.4.1（已完成，f92c242 已推送）**：motion 复显修复已提交并推送（motion.mjs+manifest.json+package.json 0.4.1），主仓库子模块指针已随本批更新。接手 agent 无需再动 Suite；如需发布版 tag 由作者决定。
5. **升级清单（卡内更新）**：依次执行——
   a. `node 工程文件/工具/构建/register-previous.cjs --card "工程文件/交付/当前/2.3.33-终端状态来源修复-20261025/东京都2051-V2.3.33.json" --write`（把 2.3.33 登记进 `旧版来源.json`/`当前续玩来源.json`，seedRefs 由工具自动推导）；
   b. `node 工程文件/工具/构建/upgrade-tool.cjs` 生成 `upgrade-manifest-3.0.0.json`（格式参照已入库的 `.cache` 外参考：清单只嵌哈希+文件名，不嵌卡本体）；
   c. `工具/构建/当前/upgrade-check.cjs` 与 `upgrade-browser.cjs` 验证（跑法看文件头注释）。
   注：`旧版来源.json`（含 135 个历史版本哈希登记）与 upgrade-tool 的 acorn 依赖（已改仓库 node_modules 解析）都已就位。
6. **打包交付**：建 `工程文件/交付/当前/3.0.0-版本统一-20261101/`（格式照抄已入库的 `2.3.33-终端状态来源修复-20261025/`）：卡 JSON + 两份配套预设 + `README.md`（安装/升级说明、SHA256、本次变更=版本号统一+配套预设思考指令修正）。同步 `交付/玩家安装与更新.md` 的现行说明指针（该文件不在 git，改完随交付本机留存）。
7. **验证**：`工具/构建/预设/bubbles-check.cjs` 等既有检查 + isolated 酒馆验证（旧版累计更新→3.0.0、刷新续玩、正文/变量保留——`2.3.33-终端状态来源修复-20261025/README.md` 的验证清单照用）+ 作者真机验收。

## 边界与注意

- 网页引擎文件（`网页独立版/src/**`）与酒馆卡**无关，不要移植**。
- 预设适配层的断言式改造（paired.cjs 的 assert/toggle）是防漂移设计：上游原版换文件会构建失败——按设计处理，不要放松断言。
- 卡内容版本语义（作者 2026-11-01 定）：兼容性热更走 3.0.x；只有改 `cxx2051-state/1` 或 `applier/1`（旧档无法继承）才升 3.1.0。本次 2.3.33→3.0.0 是纯版本统一，存档完全兼容。
- 旧档的预设是**按档钉住**的副本：站点/配套预设的修改只影响新档与手动换预设的玩家，老档由玩家自己的提示开关管（作者现档已调好：关 argon尾部+开快速思维链）。
- `.cache/`、`交付/` 新增目录默认不进 git（.gitignore /工程文件/*）：构建产物与交付物留本机，本文件与已列输入走 git。
- 旧版来源的完整版（141MB 含历代 seed 簿记）留旧电脑 `旧版来源-完整备份-本机.json`；精简版已够清单生成，未来登记新版本用 register-previous 在精简版上自洽累加。
- 交付物按共同规则留存本机；对外发布走仓库既定流程。
