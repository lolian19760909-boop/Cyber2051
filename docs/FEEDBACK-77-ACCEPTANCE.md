# 备份重复导入

关联 #77。原生故事库以文件哈希永久复用一次导入，首次导入的登记就会改变副本元数据，随后再次导入同一文件被拒绝。当前实现把身份限定到一次用户导入：失败重试复用冻结文档与已返回副本，成功后下次导入创建新副本。

产品改动集中在`工程文件/卡片源码/运行时/story-library.js`。底层迁移仍负责同操作去重、保存与读回，故事库负责“本次重试”和“新发起恢复”的区别。

- 6项新组合反例从全失败转为全通过，相关检查108项通过。
- 新组合用例已登记到完整检查入口，普通与数据克隆后备各1603项通过。
- 真实隔离酒馆导出约1.49MB备份，连续两次选择同一文件产生独立故事；继续并保存七日元后再次导入恢复原值，已游玩副本保持。
- 同一候选刷新后保存状态正常，备份字节相同，页面异常/控制台error/付费请求均0。
- 实际最终路线编号和创建时间沿Backup迁移层，档位沿故事库的既有分配。

可重跑检查：

```powershell
node --test 工程文件/测试/当前/story-import.test.cjs 工程文件/测试/当前/story-library.test.cjs 工程文件/测试/运行时/migration.test.cjs 工程文件/测试/运行时/backup.test.cjs
node 工程文件/工具/构建/当前/tests.cjs
node 工程文件/工具/构建/当前/tests.cjs --data-fallback
```

实际宿主复用`first-open-save-host.cjs`，启用`CXX_STORY_IMPORT_CHECK=1`并设置专用`CXX_EVIDENCE`，传入本批候选。已有精确SHA候选的导入/创建/保存证据可复用，再执行`story-import-host-cases.cjs`。当前结果为候选验收；公开发行按后续发布记录核对。
